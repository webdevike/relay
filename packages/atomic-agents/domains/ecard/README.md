# ecard

Read-only (shadow mode) triage, routing and drafting agents for Isaac Weber's eCard Systems work across Slack, Outlook, Linear and GitHub; nothing here posts, moves or writes to those systems.

## Agents

Each agent has one job, triggered by its input event or `manual`. Model fields: default model, with candidates `anthropic/claude-haiku-5-5` and `anthropic/claude-sonnet-5-5` unless noted. All have `thinking: off`.

## Tools and adapters

- `adapters/pack.ts`: `ecardPack`, the step adapters that lay each event out as the prompt and the tools above (`ecard.linear_issue`, `linear_search`, `isaac_open_issues`, `github_prs`, `git_log`, `workflow_runs`, `failed_log`), plus source `ecard.needs_isaac`. Tools take `repo`, `runId`, `asOf` from the item, not from the model.
- `adapters/services.ts`: `Linear` (GraphQL at `https://api.linear.app/graphql`, queries only, 30 s timeout; key from env `LINEAR_API_KEY` or the `LINEAR_API_KEY=` line of `<EVA_ROOT>/secrets/linear.env`), `GitHub` (`gh api --method GET`, 60 s timeout).
- `adapters/slack.ts`: `Slack.scan(request, source?)` (what is new since the cursors, as `clusters` plus per-conversation `failures`) and `Slack.threads(urls, source?)` (the conversations of permalinks) over two readers with one output plus `source`: `slack-desktop` (the Slack desktop app on CDP `SLACK_CDP_URL`, default `http://127.0.0.1:9333`: one `Runtime.evaluate` in the `app.slack.com/client` page calling only `READ_METHODS` (`auth.test`, `users.conversations`, `users.info`, `conversations.history`, `conversations.replies`, `conversations.info`, `search.messages`; anything else throws) with the client's session, the token never leaving the page; never navigates, clicks, types, sends, reacts or marks read; 4 minute timeout) and `claude-proxy` (`claude -p` with the claude.ai Slack connector, built-in tools disallowed, 8 minute timeout; an `{error}` answer or no authed user counts as a failure; a scan reads activity since the oldest cursor and holds each message to its own cursor, `clustersOf`). `auto` (default) tries the desktop app, then the proxy, and records `fallbackReason`; `source` on the job input or env `ECARD_SLACK_SOURCE` forces one reader with no fallback.
- `adapters/outlook.ts`: `Outlook` (inbox since a timestamp via `claude -p` with the claude.ai Microsoft 365 connector, 15 minute timeout, at most 15 emails per run, body 3000 chars).
- `adapters/promotions.ts`: `Promotions` (GitHub REST over `fetch` with `GH_TOKEN`/`GITHUB_TOKEN` or `gh auth token`, GET only, 30 s timeout: branch heads read with `If-None-Match` so an unchanged head is a 304 that costs no rate limit, `base...head` compares, the newest 100 commits of a ref, PRs, staging deployments and their latest status, branch existence, and the repos with Isaac's PRs or commits since a date via the search API) and `Ledgers` (Eva's `work/items/ENG-<n>.md` ledgers: their keys, and the `repo:` each names).
- `ecard-main-watch.ts`: `watch` keeps `main.json` in the state dir (login, the derived repos and when, per repo the last reported main head, its ETag and a head waiting for its staging deploy). Repos: Isaac's PRs and default-branch commits in the org over the last 60 days plus the ledgers' repos, kept when they have a `develop` branch, re-derived daily (`repos.derived`). First sight of a repo records its head silently. A moved head is reported once its staging deploy succeeded, failed, or an hour passed (`staging` `deployed`, `failed`, `not-deployed`; `none` for repos with no staging environment), as one `main.promoted {repo, fromSha, toSha, compare, staging, tickets, pendingOnDevelop, otherTickets}` when it carries Isaac's tickets or some are still only on develop. Tickets: ENG keys in the non-bot commits newly reachable from the new head (and merged PRs' titles and branches); Isaac's when he authored a commit or PR carrying the key or a ledger exists. Pending: his keys in commits on develop not reachable from the new head, unless a main commit with the key landed at or after them (Noah re-commits develop work onto main). The heartbeat bridge reads it only while the component's `mode` is `live`.
- `ecard-slack-fetch.ts`: state in the agent state dir. `cursor.json` `{conv: {<channel>: ts}, threads: {"<channel>:<thread ts>": ts}, mentions: ts}` (raw Slack ts; a missing key starts 24 h back; thread keys untouched 14 days drop), rewritten tmp + rename after each cluster and never past a cluster still waiting, so a crash or the 12-per-run cut neither drops nor repeats an item. `watch.json` `[{id, name?}]`: the channels read whole (each top-level post its own item). Bots, join/leave/edit events and Isaac's own messages never become items; a cluster Isaac already wrote after is skipped in code. `summary` is `<where> · <author> · <ISO>`. Messages: the whole thread (parent plus newest 30), else the operative message with the 8 before and after. When neither source reads, `fetch.completed` carries `skipped` and every cursor stays.
- `ecard-slack-digest.ts`: keeps the open lines in `open.json` in the state dir and rewrites `slack-chef.md` whole each run (`ChefSurface` in `adapters/slack.ts`, tmp + rename): `_updated <ISO> · chef_`, `## Needs your attention`, newest first, `- **<where>** (<who>) · <author> · <ISO> · <gist> · why: <reason> [permalink](<url>)`, the format Eva's heartbeat `sweep.ts` and Catch Up `catchup-build.ts` parse (`·`, `[` and `]` in the gist and reason are rewritten). `<who>` is the group DM's members or `thread`. Runs one at a time; rereads at most 20 open lines per run; a failed reread keeps every line and reports `recheckError`.
- `ecard-outlook-fetch.ts`: keeps `cursor.json` (received time plus ids) in the state dir; first run starts 24 h back.
- Proxy binary: env `CLAUDE_BIN`, else `~/.local/bin/claude`.

## Run, bench, test

From `packages/atomic-agents`:

```
bun src/cli.ts list
bun src/cli.ts run ecard-ticket-intake route --input '{"key":"ENG-1234","title":"...","creator":"Steve Arms"}'
bun src/cli.ts run ecard-outlook-fetch fetch --input '{}'
bun src/cli.ts run ecard-main-watch replay --input '{"repo":"react-client-reports-app","toSha":"588aa37d"}'
bun src/cli.ts bench ecard-ci-triage triage --input '<json>' --models anthropic/claude-haiku-5-5,anthropic/claude-sonnet-5-5
bun domains/ecard/bench/ecard.ts <agent> [--models a,b] [--tool-modes tools,code] [--concurrency 4]
bun test domains/ecard
bun run typecheck
```

`bench/ecard.ts` scores against `<home>/bench/<agent>/cases.json` (`[{id, input, expect}]`) and writes `<home>/bench/<agent>/results-<stamp>.json`. Scorers in `bench/ecard-score.ts` exist for: `ecard-slack-triage`, `ecard-ticket-mover`, `ecard-meeting-actions`, `ecard-slack-reply-drafter`, `ecard-outlook-triage`, `ecard-ticket-intake`, `ecard-ci-triage`. Tests (`test/ecard.test.ts`) use fake services and a temp Eva root, with no env gating. Run `bun install` in `packages/atomic-agents` first (the package has its own install).

## Gotchas

- Everything is read-only; the proxy prompts forbid posting, replying or changing mail, and the Linear and GitHub services have no write calls.
- Local paths required: `<EVA_ROOT>/work/elysia/` (the digest writes `slack-chef.md` there), `<EVA_ROOT>/secrets/linear.env` (or `LINEAR_API_KEY`), the `references/` knowledge files, a `gh` CLI login, and a `claude` binary with the Slack and Microsoft 365 connectors. The Slack read needs Slack desktop running with `--remote-debugging-port=9333` (Eva's `references/tools/accounts-and-messaging.md`, "Slack desktop"); without it every read goes through the slower proxy.
- `ecard-slack-reply-drafter` produces no item for a `skip` verdict.
- `ecard.git_log` and `ecard.workflow_runs` need `repo` (and `runId`) on the item; `failed_log` returns the last 6000 chars.
- Replays read Linear and GitHub as of the item's moment (state and comments replayed from issue history).
