# atomic-agents: plan

Replace skills with atomic specialist agents. A **component** = one narrow agent (small prompt, inlined knowledge, its tools, best model) + its jobs (manual, cron, on-event) + an output contract of typed events. Assistants and Relay subscribe to events instead of the 30-minute `eva-heartbeat` sweep.

**Built (v0, Effect 4.1.4 LTS, Bun, own install, opt-in):** `Component.ts` contract (`define`, `job`, `Manual`/`Cron`/`OnEvent`), `Event.ts` (`AgentEvent` envelope, `EventBus`: append-only `~/.config/relay/atomic-agents/events.ndjson` (`ATOMIC_AGENTS_HOME`, Relay's data dir) tailed into a `PubSub`; the file is the cross-process bus), `Settings.ts` (the consumer config, below), `Model.ts` (`ModelRunner.omp`: `omp -p --mode json` with no tools, skills, rules or repo context, so swapping models is one string; reports served provider and cost; `openrouter/<vendor>/<model>` ids use omp's openrouter provider with the key from config `openRouterKeyFile` (or `OPENROUTER_API_KEY`), the key reaches no other call, and Anthropic/OpenAI ids are refused on OpenRouter), `Runtime.ts` (`Runner`: one run at a time per component, `job.started|succeeded|failed` around every run, each run resolves its model from the config in force; `serve` arms cron and event triggers and re-arms crons when config changes), `Service.ts` (`serve` as its own LaunchAgent `ai.eva.atomic-agents`, KeepAlive, log `<home>/logs/serve.log`; `service install` copies the package into `<home>/app` and installs its production deps there, so the service never runs from a checkout; `service install|uninstall|status`), `cli.ts` (`list run bench rate wins use emit events serve service`). Pilot: **prop-render**, an object description → Blender `build()` script → GLB of the bare model plus a render on a fixed stage (floor, three lights, auto-framed camera) → `prop-render/render.completed {image, glb, script, model, attempts, seconds, cost}`. It retries once with Blender's traceback. Why this pilot: the result can be judged at a glance, it runs locally in about 2 s plus the model call, and since the stage is fixed only the model varies.

**Core vs consumer (Isaac, 2026-11-14):** the core (runtime, bus, model runner, built-in components with code defaults) lives here. The consumer side lives in `~/.config/relay/atomic-agents`: `config.json`, `events.ndjson`, `runs/`, `logs/`, `app/`. `config.json` (Effect Schema `SettingsFile`, strict: unknown keys, components, jobs and bad crons are rejected) holds `openRouterKeyFile` and per component `enabled`, `model`, `candidates`, `thinking`, `cron: {<job>: "<expr>"}`; absent keys fall back to the code defaults. **Live:** the service polls the file every second; a valid edit swaps in atomically, a bad one keeps the last good config and emits `atomic-agents/config.rejected`. Every applied change emits `atomic-agents/config.changed {by, source: use|set|file, changes: [{path, old, new}], undo, config}`; `undo` is a JSON merge patch (RFC 7396) that restores the old values. Changing config: `atomic-agents use <component> <model> [--by <who>]` (what a bake-off winner does; `wins` prints the command), or emit `atomic-agents/config.set {by, patch}` (merge patch) for the service to apply; emitting a `config.changed`'s `undo` as `config.set` reverts it.

**Next, in order:**
1. **Test Bench:** `bench` runs one input across the candidates; `rate <run-a> <run-b> a|b|tie` writes a pairwise `pair.picked` event (as in the 2026-10-28 reel bench), `wins` prints each model's win rate (ties count half) and the `use` command that promotes the winner into config.json. Then add an `exp`-format writer (`work/experiments/<date>-prop-render/`) so the existing read-only Test Bench page lists the arms, and add a side-by-side A/B pick to the arm panel.
2. **Relay:** the host tails the journal and broadcasts `agents.event` frames (phone and desktop), and assistants get a per-assistant subscription list (`agents.json` `subscribes: ["prop-render/render.completed"]`) delivered through the existing `/assistant/say`.
3. **Migration:** move one heartbeat source at a time into a component whose cron job emits `<source>.item` events (start with the Gmail and Slack collectors in `jobs/eva-heartbeat/scripts/sweep.ts`). Then delete that source's branch from `SOURCE_AGENT`. Visual skills next (`ui-check`, as a ui-review component), then retire each skill once its component wins its bake-off.

**Decided (2026-11-14):** home is Relay's data dir; `serve` is its own LaunchAgent, not the Relay host, running the installed copy in `<home>/app`; ratings are pairwise picks; model choice lives in config.json, applied live. **Open:** second visual pilot (image gen via Studio backends, or ui-review).

**Size:** v0 is about 800 lines. Bench writer + A/B pick UI about 2 days; host bridge + assistant subscriptions about 2 days; each migrated heartbeat source or skill 0.5 to 1 day.
