## Phase Goal

**As a** EvaOS user, **I want to** see and act on my Eva data (workspaces, todos, jobs, habits, meetings) from the new app, **so that** I can work from it daily while every write to the Eva checkout still goes through EvaFs.

<objective>
Wave 0 data rules for Jobs: a byte-preserving line editor for `job.md` frontmatter (`JobDoc`), runner-parity validation and durations, next-due and label helpers, and a read-only reader for `jobs/` and `jobs/.runs/`.

Purpose: CONTEXT "Jobs edits change only the edited lines"; JOBS-01..03. Research found the UI-SPEC disagrees with the real runner on keep, names, units, schedule labels and run states; this plan follows the runner (`job-run.ts`, `jobs.rs`) and records each deviation:
- D1: Keep is a DURATION (default 30m, "How long the session stays open for replies"), zero allowed; UI-SPEC's integer "Keep the last n runs" is not used.
- D2: names `^[a-z0-9][a-z0-9-]*$`; copy "Use lowercase letters, numbers and hyphens, starting with a letter or number."
- D3: full runner duration syntax accepted; copy "Use a number followed by m, h or d, like 30m, 2h or 1d."; zero rejected for Interval and Max run with "Must be more than zero."
- D4: schedule label "Every {raw}" or "Manual"; no "Daily 08:30".
- D5: "Write at least one step." added.
- D6: run badge mapping running / ok / failed / never run, unknown state shown raw.
- D14: no yaml parse; line-oriented frontmatter.
Output: jobs.ts and jobs-read.ts with tests (subpath imports, index.ts untouched).
</objective>
