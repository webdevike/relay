# Widgets are composed from shared primitives (Isaac, 2026-10-06)

Never build a ```ui widget (or any screen element) as a one-off. Break it into base elements in
`src/ui/` (and helpers in `src/lib/`), then have the widget in `src/agents/` only orchestrate them.
Before writing UI, check what already exists and reuse it; if a piece is missing, add it as a
primitive first, then use it.

Every ```ui widget must also render in EvaOS, Eva's desktop app (`~/Eva/apps/evaos/src/rich/widgets.rs`,
Rust/GPUI). Adding or changing a widget spec here means the same change there, with a parser test on
each side; see the `relay-widgets` skill.

Current primitives:

- Links: `lib/links.ts` `openExternal`, `ui/LinkButton.tsx` (text / icon / overlay). Never call `Linking.openURL` from a widget.
- Pagination: `ui/Pager.tsx` (`usePager`, `Pager`; `fitPage` sizes it to the shown page; inside a Catch Up `SwipeCard` it blocks the card's sideways pan via `useSwipeCardGestures`), `ui/PageControls.tsx` (`PageStepper`, `PageCounter`, `PageDots`), `ui/TabPager.tsx` (`SegmentedTabs` over a fit-height `Pager`: tap or swipe between tab panes, the selected tab follows the swipe; every multi-tab widget uses it). Never hand-roll a paging `ScrollView`, chevrons, or a tab bar that swaps panes without swiping.
- Media: `ui/ImageFrame.tsx`, `ui/VideoFrame.tsx` (aspect-sized `expo-video` surface, center play, spinner, full-screen corner button), `ui/MediaTransport.tsx` (`MediaTransport` row plus `PlayButton`, `SeekBar`; shared by audio and video, times via `lib/format.ts` `mediaClock`), `ui/MediaPlaceholder.tsx` (host-not-connected and failed states), `ui/ImageCaption.tsx`, `ui/OverlayTag.tsx` (corner labels/badges on media), `agents/ZoomableImage.tsx` (pinch/pan/double-tap), `agents/ImageViewer.tsx` (full-screen pager).
- 3D: `ui/ModelView.tsx` (sized frame around the native glTF view in `modules/model-view`, SceneKit + GLTFKit2: fit to frame, drag orbits, pinch zooms, optional spin, spinner while loading, placeholder on failure). Never put a web view or three.js in a widget for 3D.
- Tones: `theme.ts` `ToneToken`, `toneFill` (low-alpha tone surface, raised surface for muted), `withAlpha`; `agents/tone.ts` `toneColor` maps a spec `Tone` to a `ToneToken`. Never hardcode a tinted `rgba`.
- Controls: `ui/Button` (`tone` tints the primary fill or a secondary/ghost label), `ui/TextField` (bordered input, hairline steps darker on focus), `ui/SegmentedTabs` (`size="large"` for a 44pt screen-level switch, e.g. home's Work | Personal), `ui/Collapse` (chevron header that shows/hides its content), `ui/ChecklistRow` (checkable row) on `ui/CheckMark` (the static done/not-done box).
- Account scope: `lib/profile.ts` (`scopeOrder`, `inProfile`, `orderAssistants`) reads the settings store's `ompProfile` (work | personal). Any session list or launch must go through it rather than reading `AgentSession.account` directly.
- Cards: `ui/Card` (raised floating panel; the ask and habit gate cards), `ui/OptionRow` (selectable choice with description, right badge and optional `leading` element), `ui/TimerReadout` (large m:ss countdown over a `ProgressBar`). Photos: `lib/photo.ts` `choosePhoto` (camera or library, scaled JPEG ready to send).
- Content: `ui/DataTable` (hairline rows, muted header, content-sized columns that fill or scroll sideways, tabular right-aligned figures), `ui/ProgressBar`, `ui/Callout` (tone fill, tone hairline, tone icon), `ui/BlockQuote` (left bar; markdown blockquotes use it too), `ui/ListItem` (content indented by the marker column with the marker pinned absolutely in it, never a `flex: 1` row: shrink-to-fit chat bubbles mis-size flexed text; markdown lists use it too), `ui/TimelineItem` (dot on a hairline rail, right-aligned time), `ui/Avatar` (round photo, initials fallback), `agents/CodeBlock.tsx` (Prism highlighting, copy).
- Assistant portraits: `lib/portrait.ts` (`portraitSeed(agent)` = the registry's `avatar` sent on `assistant.agents`, else the id; `portraitSvg(seed)` DiceBear notionists, the generator Relay desktop uses, memoized) drawn by `ui/Portrait` (Skia `ImageSVG` on a light disc, initials `Avatar` without Skia). Every place an assistant appears uses it: the Assistants list, the Assistants widget, the chat header and call screen (`AvatarRing` `seed`), the Catch Up handoff sheet. Never show an assistant's initial.
- Replies: `agents/WidgetActions.tsx`. The agent screen wraps the transcript in `SessionWidgetActions`; `useWidgetActions()` returns `{ reply(text) }` (an `agent.reply` with `submit: true` to that session) or null outside a session, where reply buttons and inputs render disabled.
- Live ```openui widgets: `parseBlocks` keeps an openui fence as `{ kind: "openui", code, partial }`; `OpenUIBlock` (in `MessageText.tsx`) owns one `createOpenUIRuntime` per fence while mounted, feeds it each streamed version (`agents/openui.ts` `syncOpenUIRuntime`, so `$variable` state survives streaming) and redraws on state changes via `useSyncExternalStore`. `agents/OpenUIRuntime.tsx` exposes the runtime to widgets: a button with `action` runs `dispatch` locally (instant, no network), then sends the returned `reply` / opens the `url` like a plain button (`pressButton`); an input with `bind` shows the spec's `value` and writes edits with `setInput`.
- Agent-made UI (```html-widget and ```mantine-widget): `ui/HtmlFrame` (sandboxed `react-native-webview`: transparent, sized to its content up to `maxHeight`, no zoom/callouts/link previews, drags scroll the chat; CSP blocks all network, only `about:` loads, a tapped http(s)/mailto link goes to `onOpenLink`). `runtime="html"` shows `code` as an HTML fragment, `runtime="mantine"` runs it as JSX on real Mantine 9.7 + @mantine/charts. Its pages come from the shared package `@relay/widget-runtime` (`packages/widget-runtime`, also used by Relay desktop): `frame.ts` (`htmlFrameDocument` / `mantineFrameDocument`: palette as `--fg`/`--muted`/`--border`/`--surface`/`--raised`/`--accent`/... - Approvals and notification actions (`src/inbox/`): `answer.ts` holds the rules (an ordinary approval is one tap; a destructive one, `requiresBiometric`, needs Face ID via `biometric.ts` and is sent as `confirmed: "biometric"`; deny never needs it; an ask takes an option's label or number, else the typed text; there is no "always allow"). `categories.ts` registers the lock-screen actions the host names in a push (`INBOX_CATEGORY` in the protocol), `respond.ts` runs a tapped action (waking the connection first), `background.ts` and `withdraw.ts` remove a notification when it is answered elsewhere (`inbox.resolve` over the socket, a silent push when the app is not running). `agents/ApprovalCard.tsx` is the in-session card (`SessionApprovalCard` wires it). Native modules: `expo-local-authentication`, `expo-task-manager`; the app config adds the Time Sensitive entitlement and `remote-notification` background mode, so changing them needs an Xcode rebuild.
- Chat look (the Eva screen): `ui/AvatarRing` (65pt translucent ring around a transparent hole, blurred name pill; `breathing` while the agent works), `ui/FloatingPill` (opaque rounded bar with leading/trailing slots that floats over a scrolling page and grows into a tall card with `expanded`) with `FloatingPillInput` (its borderless multiline field), `ui/TopBlur` (stacked `BlurView`s that blur what scrolls under a floating header) with `ui/EdgeFade` (top or bottom `edge` fade to the page colour, `strength`/`solid`; Skia gradient, banded Views without Skia), `ui/ExpandableContent` (children clipped to a max height with a bottom fade and Show more / Show less; `onExpanded(growth)` lets a scroller keep the clamp in place), `ui/TypingDots` (iMessage's "is typing" bubble: three dots lighting in turn in a left-aligned bubble of the given `fill`, VoiceOver `label`, still under Reduce Motion; assistant threads show it while `snapshot.busy` and the newest row is not an assistant reply with text), `ui/TypingBubble` (agent transcripts' quiet activity line: pulsing sparkle, label, elapsed seconds; `agents/ActivityRow`, opened and closed by `ui/GrowIn`), `ui/GrowIn` (a transcript row that just arrived opens from zero height, clipped, and `open={false}` closes one the same way, so neighbours glide instead of jumping; at rest it sets `height: "auto"` outright, because a key dropped from an animated style keeps its last value, and pinned rows let streamed lines spill over the rows below), `ui/useInvertedChatScroll` (follow mode for inverted transcripts; its handlers turn on native anchoring, `maintainVisibleContentPosition`, only while the reader is away from the newest row: anchoring a follower pushed each new row below the fold for a frame). `theme.ts` `bubbleUser` is the user's own chat-bubble fill. `IconButton` takes `accessibilityLabel`, `glyphSize`, `disabledOpacity`; `MessageText` takes `large` for 17pt chat text.
- Chat images (the Eva screen): `ui/AttachmentTray` (row of 72pt square thumbnails queued on a composer, each with an x that removes it), `agents/MessageImageStack` (a message's images as `ImageFrame`s stacked above its text: host refs are fetched with `requestAgentImage` into `useAgentsStore().images[sessionId]`, or `local` photos shown directly; tap reports the loaded uris and index for `ImageViewer`), `ui/ImageFrame` `radius`, `lib/photo.ts` `chooseLibraryPhotos(limit)` (multi-select library pick, each scaled and encoded like `choosePhoto`; `Photo` now carries `width`/`height`) and `lib/clipboard.ts` `clipboardHasImage` / `readClipboardPhoto`. The composer's "+" opens an action sheet: Camera, Photo library, Paste image. Markdown images in message text: `markdown.ts` turns `![alt](src)` (inline, standalone or linked) into `image` blocks; `agents/MarkdownImages` shows a message's images as left-aligned 170pt tiles (22 radius, 12 gap, 110 to 220 high from `Image.getSize`, cover) with one `ImageViewer` over all of them. - Mac live view (`app/screen.tsx`): `ui/VncView` (noVNC in a `react-native-webview`, connected to a host `/vnc` bridge URL; `ref.send` types text and keys). The page is `apps/mobile/vnc/viewer.ts` bundled with `@novnc/novnc` by `vnc/build.mjs` into the generated `src/vnc/viewerHtml.ts` (`pnpm vnc:build` after changing either; no CDN). - Existing: `ui/Pill`, `ui/IconButton` (`tone="overlay"` for white-on-glass controls over media), `ui/Text`, `ui/Row`, `ui/Sheet`.
- Status and suggestions: `ui/Banner` (`busy` leads with a spinner in the tone, `icon` with an SF Symbol instead, `detail` adds a muted second line capped by `detailLines`; the agent screen's "Generating handoff" banner and goal strip), `ui/Chip` (small tappable capsule with an optional leading glyph or spinner, `selected` tints it; the background-job chips), `ui/SuggestionList` (raised card of autocomplete rows: title, hint beside it, detail under it; the typed reply's `/` menu, matched by `lib/slash.ts`). `agents/SessionActivity.tsx` composes the first two at the bottom of the chat card. - Home widgets (`src/home/widgets/`, iPhone home screen style, separate from ```ui chat widgets): `layout.ts` is the pure model (kinds, small/medium/large sizes per kind, default layout, add/remove/resize/move, flow rows, slots with rows of differing heights; tested) persisted as the settings store's `homeWidgets` (v2 migration; v3 and v4 add the `apps` and `catchup` widgets once through `withWidgetOnce`). `WidgetParts.tsx` holds the pieces every kind builds from (`WidgetSurface` solid 22pt card that is one VoiceOver element with the grid's actions, or with `href={null}` a plain card whose rows carry them, `WidgetHeader`, `WidgetFigure`, `WidgetLink`, `WidgetNote`); `kinds/*` wire store data into them and `registry.ts` names them. `WidgetGrid` does jiggle mode and drag, `WidgetMenu` the long-press menu (an in-tree overlay so the opening finger can carry on into a drag), `app/add-widget.tsx` the gallery (a native sheet); `ui.ts` is their shared transient state and `runWidgetAction`. `home/apps.ts` `useHomeApps` lists Home's apps (the `apps` widget's rows, `home/AppRow`, whose `AppGlyph` is the gradient icon square); `usage/Rings` takes a `stroke` for small sizes.
- Swipe decks (Catch Up, `app/catch-up.tsx`): `ui/SwipeCard` (follows the finger with up to 12° tilt; a release past 35% of the width or a fling throws it off that side, else it springs back; haptic at the threshold; `ref.swipe(direction)` throws it from a button; with `upEnabled`, a drag up that starts on a `SwipeUpHandle` lifts the card without tilt and a release past 14% of the height or an upward fling throws it up; `onLongPress` fires for a finger held still 450 ms (`LongPressGestureHandler` running alongside the pan, never a Pressable root, which blocks scroll and pans); `overlay` gets `SwipeSignals` `{horizontal, up}` drag progress). Inside a card face, wrap the regions that may start a swipe up (header, footer, a body that fits) in `SwipeUpHandle`, and use `SwipeCardScrollView` for a body that overflows: it waits for the card pan so sideways drags still throw, and plain vertical drags scroll. `ui/SwipeDeck` (top card plus the next one waiting smaller underneath, which grows into place as the top leaves, and a third preloaded behind once the deck settles; every card stays mounted while in those slots, so a throw only changes role values; `onSwipe(item, direction)`; `canSwipeUp(item)`, `onLongPress(item)`; memoize the face you pass to `renderCard`), `ui/SwipeActionOverlay` (tint plus a `RadialProgress` ring around a glyph and the action's label: a corner for left/right, centred at the top for up), `ui/RadialProgress` (ring that fills from an Animated value: two rotating half-arcs in clipped halves, glyph centred). Performance rule: deck motion runs on React Native's native `Animated` driver (legacy `PanGestureHandler` + `Animated.event(useNativeDriver)`), not Reanimated: Reanimated 4.1 on iOS commits every frame through the shadow tree, which re-rounds the whole tree's layout and makes every mounted ScrollView walk its subviews, so drag cost grew with the length of the markdown on the cards. Keep the animated graph fixed per card (roles are 0/1 values set with `setValue`); swapping animated styles on a mounted view left stale native transforms. No Skia canvases on moving cards. Never hand-roll a pan-to-dismiss card. Data: host `catchup.list` / `catchup.mark` -> `state/catchup.ts`; deck order and "Keep Unread" (to the back, this session only) are `lib/catchup.ts` `deckCards`; the face is `catchup/CatchUpCardView` (memoized; markdown body via `MessageText`; a bounced card shows the assistant's reason in a `Callout`). Handoff: swipe up or the purple send button sends `catchup.handoff` to the card's `assistant` (`lib/catchup.ts` `defaultAssistant`: eCard work to Astra, the rest to Nova; theme colour `handoff`); a long press opens `catchup/HandoffSheet` (an RN `Modal` page sheet: pick any registry assistant, optional note). The host marks it read and records `handedTo`; an assistant that can't act runs `bun ~/Eva/.omp/tools/catchup.ts bounce <id> "<reason>"`, which makes it unread and first in the deck, with a "<Agent> couldn't act" banner.
- Catch Up notes (`catchup/NoteSheet.tsx`): the pencil in a card's footer opens a page sheet asking "Why does or doesn't this need you?" with signal chips (`needs-me`, `not-actionable`, `fyi`) and free text; `noteCatchUp` sends `catchup.note`, the host appends it to Nova's `catchup-notes.jsonl` and answers `catchup.noted` (toast via `useCatchUpStore().noteAnswer`). The card stays in the deck. A card's `why` line (from the feed) sits under its title.
- OTA updates (`lib/otaUpdates.ts`): expo-updates against the self-hosted server in `apps/ota-server` (Bun, Expo Updates protocol v1, LaunchAgent `com.ike.relay-ota` on 127.0.0.1:8477, tailnet-only `https://isaacs-mac-mini.tail80fdb0.ts.net:8447`). `useOtaUpdates` (root layout) checks, fetches and reloads on launch and on every return to the foreground; Settings' App update row shows the running bundle (`runningUpdate`) and checks on demand (`applyLatestUpdate`). Both are no-ops in `__DEV__`. Ship JS with `pnpm ota:publish` (repo root); `runtimeVersion` follows `expo.version`, so bump the version whenever native code changes or old builds would load a bundle they cannot run. `pnpm ota:install` rebuilds and reloads the server.

A widget file should read as layout: primitives wired to its spec, with no styling or gesture
logic that another widget could need.
