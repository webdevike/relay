# Widgets are composed from shared primitives (Isaac, 2026-10-06)

Never build a ```ui widget (or any screen element) as a one-off. Break it into base elements in
`src/ui/` (and helpers in `src/lib/`), then have the widget in `src/agents/` only orchestrate them.
Before writing UI, check what already exists and reuse it; if a piece is missing, add it as a
primitive first, then use it.

Every ```ui widget must also render in EvaOS, Eva's desktop app (`~/Eva/apps/evaos/src/rich/widgets.rs`,
Rust/GPUI). Adding or changing a widget spec here means the same change there, with a parser test on
each side; see the `relay-widgets` skill.

Current primitives:

- Links: `lib/links.ts` `openExternal`, `ui/LinkButton.tsx` (text / icon / overlay). Never call `Linking.openURL` from a widget.
- Pagination: `ui/Pager.tsx` (`usePager`, `Pager`), `ui/PageControls.tsx` (`PageStepper`, `PageCounter`, `PageDots`). Never hand-roll a paging `ScrollView` or chevrons.
- Media: `ui/ImageFrame.tsx`, `ui/VideoFrame.tsx` (aspect-sized `expo-video` surface, center play, spinner, full-screen corner button), `ui/MediaTransport.tsx` (`MediaTransport` row plus `PlayButton`, `SeekBar`; shared by audio and video, times via `lib/format.ts` `mediaClock`), `ui/MediaPlaceholder.tsx` (host-not-connected and failed states), `ui/ImageCaption.tsx`, `ui/OverlayTag.tsx` (corner labels/badges on media), `agents/ZoomableImage.tsx` (pinch/pan/double-tap), `agents/ImageViewer.tsx` (full-screen pager).
- 3D: `ui/ModelView.tsx` (sized frame around the native glTF view in `modules/model-view`, SceneKit + GLTFKit2: fit to frame, drag orbits, pinch zooms, optional spin, spinner while loading, placeholder on failure). Never put a web view or three.js in a widget for 3D.
- Tones: `theme.ts` `ToneToken`, `toneFill` (low-alpha tone surface, raised surface for muted), `withAlpha`; `agents/tone.ts` `toneColor` maps a spec `Tone` to a `ToneToken`. Never hardcode a tinted `rgba`.
- Controls: `ui/Button` (`tone` tints the primary fill or a secondary/ghost label), `ui/TextField` (bordered input, hairline steps darker on focus), `ui/SegmentedTabs` (`size="large"` for a 44pt screen-level switch, e.g. home's Work | Personal), `ui/Collapse` (chevron header that shows/hides its content), `ui/ChecklistRow` (checkable row) on `ui/CheckMark` (the static done/not-done box).
- Account scope: `lib/profile.ts` (`scopeOrder`, `inProfile`, `orderAssistants`) reads the settings store's `ompProfile` (work | personal). Any session list or launch must go through it rather than reading `AgentSession.account` directly.
- Cards: `ui/Card` (raised floating panel; the ask and habit gate cards), `ui/OptionRow` (selectable choice with description and right badge), `ui/TimerReadout` (large m:ss countdown over a `ProgressBar`). Photos: `lib/photo.ts` `choosePhoto` (camera or library, scaled JPEG ready to send).
- Content: `ui/DataTable` (hairline rows, muted header, content-sized columns that fill or scroll sideways, tabular right-aligned figures), `ui/ProgressBar`, `ui/Callout` (tone fill, tone hairline, tone icon), `ui/BlockQuote` (left bar; markdown blockquotes use it too), `ui/ListItem` (marker column + content; markdown lists use it too), `ui/TimelineItem` (dot on a hairline rail, right-aligned time), `ui/Avatar` (round photo, initials fallback), `agents/CodeBlock.tsx` (Prism highlighting, copy).
- Replies: `agents/WidgetActions.tsx`. The agent screen wraps the transcript in `SessionWidgetActions`; `useWidgetActions()` returns `{ reply(text) }` (an `agent.reply` with `submit: true` to that session) or null outside a session, where reply buttons and inputs render disabled.
- Live ```openui widgets: `parseBlocks` keeps an openui fence as `{ kind: "openui", code, partial }`; `OpenUIBlock` (in `MessageText.tsx`) owns one `createOpenUIRuntime` per fence while mounted, feeds it each streamed version (`agents/openui.ts` `syncOpenUIRuntime`, so `$variable` state survives streaming) and redraws on state changes via `useSyncExternalStore`. `agents/OpenUIRuntime.tsx` exposes the runtime to widgets: a button with `action` runs `dispatch` locally (instant, no network), then sends the returned `reply` / opens the `url` like a plain button (`pressButton`); an input with `bind` shows the spec's `value` and writes edits with `setInput`.
- Agent-made HTML: `ui/HtmlFrame` (sandboxed `react-native-webview`: transparent, sized to its content up to `maxHeight`, no zoom/callouts/link previews, drags scroll the chat; CSP blocks all network, only `about:` loads, a tapped http(s)/mailto link goes to `onOpenLink`), its page built by `lib/htmlFrame.ts` (`htmlFrameDocument`: palette as `--fg`/`--muted`/`--border`/`--surface`/`--raised`/`--accent`/... CSS variables, system font, `window.relay` = `{ theme, reply(text) }`; `reply` only sends during a user gesture). `parseBlocks` keeps a ```html-widget fence as `{ kind: "html", html, partial }`; `agents/HtmlWidget.tsx` shows the frame's spinner while `partial`, then the page, with `relay.reply` wired to `useWidgetActions().reply`.
- Approvals and notification actions (`src/inbox/`): `answer.ts` holds the rules (an ordinary approval is one tap; a destructive one, `requiresBiometric`, needs Face ID via `biometric.ts` and is sent as `confirmed: "biometric"`; deny never needs it; an ask takes an option's label or number, else the typed text; there is no "always allow"). `categories.ts` registers the lock-screen actions the host names in a push (`INBOX_CATEGORY` in the protocol), `respond.ts` runs a tapped action (waking the connection first), `background.ts` and `withdraw.ts` remove a notification when it is answered elsewhere (`inbox.resolve` over the socket, a silent push when the app is not running). `agents/ApprovalCard.tsx` is the in-session card (`SessionApprovalCard` wires it). Native modules: `expo-local-authentication`, `expo-task-manager`; the app config adds the Time Sensitive entitlement and `remote-notification` background mode, so changing them needs an Xcode rebuild.
- Chat look (the Eva screen): `ui/AvatarRing` (65pt translucent ring around a transparent hole, blurred name pill; `breathing` while the agent works), `ui/FloatingPill` (opaque rounded bar with leading/trailing slots that floats over a scrolling page and grows into a tall card with `expanded`) with `FloatingPillInput` (its borderless multiline field), `ui/TopBlur` (stacked `BlurView`s that blur what scrolls under a floating header) with `ui/EdgeFade` (top or bottom `edge` fade to the page colour, `strength`/`solid`; Skia gradient, banded Views without Skia), `ui/ExpandableContent` (children clipped to a max height with a bottom fade and Show more / Show less; `onExpanded(growth)` lets a scroller keep the clamp in place), `ui/TypingBubble` (the animated "is typing" bubble). `theme.ts` `bubbleUser` is the user's own chat-bubble fill. `IconButton` takes `accessibilityLabel`, `glyphSize`, `disabledOpacity`; `MessageText` takes `large` for 17pt chat text.
- Chat images (the Eva screen): `ui/AttachmentTray` (row of 72pt square thumbnails queued on a composer, each with an x that removes it), `agents/MessageImageStack` (a message's images as `ImageFrame`s stacked above its text: host refs are fetched with `requestAgentImage` into `useAgentsStore().images[sessionId]`, or `local` photos shown directly; tap reports the loaded uris and index for `ImageViewer`), `ui/ImageFrame` `radius`, `lib/photo.ts` `chooseLibraryPhotos(limit)` (multi-select library pick, each scaled and encoded like `choosePhoto`; `Photo` now carries `width`/`height`) and `lib/clipboard.ts` `clipboardHasImage` / `readClipboardPhoto`. The composer's "+" opens an action sheet: Camera, Photo library, Paste image. Markdown images in message text: `markdown.ts` turns `![alt](src)` (inline, standalone or linked) into `image` blocks; `agents/MarkdownImages` shows a message's images as left-aligned 170pt tiles (22 radius, 12 gap, 110 to 220 high from `Image.getSize`, cover) with one `ImageViewer` over all of them. The Eva thread pulls them out above the bubble (`topLevelImages(text)` plus `MessageText skipImages`); elsewhere `MessageText` renders them inline. `src` is `http(s)://` or a drop path (`imageSrcKind`, resolved by `useDropSrc`); a bare Mac path shows the caption `Image on the Mac: <name>`.
- Eva's computer (`app/eva-computer.tsx`, `eva/computer.ts`): full-screen `react-native-webview` of Eva's contained Selkies browser (`EVA_COMPUTER_URL`; see `workflows/eva-browser.md`). `ui/ChromePill` (translucent white capsule: glyph + label, or a row of transparent `IconButton`s) and `ui/Toast` (short dark message; `lib/useTransientMessage` shows and clears it) are the reusable chrome. Pinch zoom works only because `ALLOW_PINCH_ZOOM_JS` rewrites the page's viewport meta; keep it injected.
- Mac live view (`app/screen.tsx`): `ui/VncView` (noVNC in a `react-native-webview`, connected to a host `/vnc` bridge URL; `ref.send` types text and keys). The page is `apps/mobile/vnc/viewer.ts` bundled with `@novnc/novnc` by `vnc/build.mjs` into the generated `src/vnc/viewerHtml.ts` (`pnpm vnc:build` after changing either; no CDN). It loads with a `file://` base on purpose: that keeps it a secure context, which noVNC needs for Apple's Screen Sharing auth. Its contract is `src/vnc/messages.ts`; each connection needs a fresh single-use ticket (`requestVncAccess` -> `useVncStore().access`), and Screen Sharing's login lives in Keychain via `src/vnc/credentials.ts`.
- Existing: `ui/Pill`, `ui/IconButton` (`tone="overlay"` for white-on-glass controls over media), `ui/Text`, `ui/Row`, `ui/Sheet`.
- Status and suggestions: `ui/Banner` (`busy` leads with a spinner in the tone, `icon` with an SF Symbol instead, `detail` adds a muted second line capped by `detailLines`; the agent screen's "Generating handoff" banner and goal strip), `ui/Chip` (small tappable capsule with an optional leading glyph or spinner, `selected` tints it; the background-job chips), `ui/SuggestionList` (raised card of autocomplete rows: title, hint beside it, detail under it; the typed reply's `/` menu, matched by `lib/slash.ts`). `agents/SessionActivity.tsx` composes the first two at the bottom of the chat card. A slash command sent from the phone shows as running until the session answers it (`lib/sentCommand.ts`, `state/agents.ts` `sent`, `agents/useSentCommand.ts`): the transcript's newest row plus "Running /name", or the handoff banner for `/handoff`; command rows read as a `ui/Pill` chip (`lib/slash.ts` `commandWord`).

A widget file should read as layout: primitives wired to its spec, with no styling or gesture
logic that another widget could need.
